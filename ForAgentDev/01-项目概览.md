# 01 · 项目概览

> 最后更新：2026-08-16 · 关联：初始建仓

## 1. 项目定位

**VectorDev** 是「团队多 Agent 协作开发」的落地仓库，解决的核心问题是：

> 一个任务如何高效地并行派发给多个 AI Agent，并在统一平台上看板、跟踪、聚合产出。

底座技术：[Multica](https://multica.ai) —— 给已有 Coding Agent（Claude Code / Codex / OpenClaw / Gemini 等）套一层项目管理壳（Issue / Task / Kanban）。

## 2. 为什么存在

- Multica 原生分配模型是 **1:1**（一个 Issue 一个负责人），**不支持**「一个 Issue 同时派给多个 Agent」；
- Multica 的 Squad（小队）是 leader **串行路由**，不提供并发；
- 现实场景需要：**同一任务，多视角/多分片并行执行**，再聚合对比。

因此我们实现 `multica-fanout`：用官方支持的「父 Issue + 子 Issue 并行」模式，封装成开箱即用的 CLI。

## 3. 当前项目清单

| 项目 | 目录 | 说明 | 状态 |
| --- | --- | --- | --- |
| multica-fanout | `multica-fanout/` | Multica 多 Agent 并行派发 CLI（dispatch / status / aggregate） | ✅ 可用 v0.1.0 |

## 4. 目标场景（典型用例）

```
任务：竞品调研（1 个任务）
  └─ fanout dispatch --agents "codex,claude,gemini,hermes,opencode,cursor"
       ├─ 父 Issue MUL-100（聚合点）
       ├─ 子 MUL-101 codex   → 视角 1  → 产出 view-1-codex.md
       ├─ 子 MUL-102 claude  → 视角 2  → 产出 view-2-claude.md
       ├─ ...（6 个子任务并行 todo）
       └─ fanout aggregate → 6 份产出落盘 + 汇总报告回写父 Issue
```

## 5. 路线图

- [ ] **前端管理面板**：批量派发 UI + 实时执行看板 + 结果对比视图（下一阶段）
- [ ] WebSocket 实时进度推送（复用 Multica /ws 事件）
- [ ] 多视角产出 diff 对比高亮
- [ ] 多项目支持：仓库内新增项目时遵循本文档结构扩展

## 6. 技术栈总览

| 层 | 技术 |
| --- | --- |
| CLI | Node.js ≥ 18（ESM）、commander |
| 底座 | Multica CLI（Go 服务端 + PostgreSQL + WebSocket） |
| 测试 | Node 内置 test runner + fake Multica mock（无需真实环境） |
| 未来前端 | React + Vite + Tailwind（见 `05-协作规则.md` 的技术选型约定） |

## 7. 边界与风险

- **授权**：Multica 为 Apache-2.0 但含商业限制条款（禁止对外提供 Hosted 服务 / 移除品牌信息）。若平台要对外商业化，需法务确认。
- **并发冲突**：多 Agent 并行必须遵守产出隔离（见 `05-协作规则.md` §5），否则文件冲突。
- **依赖变更**：Multica CLI 命令以 `--help` 为准，本文档命令可能与新版本有差异。
