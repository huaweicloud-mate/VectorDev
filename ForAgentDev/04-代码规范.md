# 04 · 代码规范

> 最后更新：2026-08-16 · 适用：multica-fanout（Node.js ESM）

## 1. 语言与运行时

- JavaScript（ESM），Node.js ≥ 18；
- 不使用 TypeScript（当前阶段保持零构建步骤；若引入需在本文档记录迁移理由）；
- 不引入 linter 之外的额外构建链（Vite 仅用于未来前端项目）。

## 2. 命名

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 文件/目录 | kebab-case | `fake-multica.mjs`、`src/dispatch.js` |
| 变量/函数 | camelCase | `issueCreate`、`resolveAgents` |
| 常量 | UPPER_SNAKE | `BIN_CMD`、`STATUS_DONE` |
| 类 | PascalCase | `MulticaError` |
| 布尔变量 | is/has/can 前缀 | `isDone`、`hasFlag` |
| 命令参数 | kebab-case（CLI 惯例） | `--agents-file`、`--no-wait` |

## 3. 文件组织

```
<project>/
├── bin/<name>.js      # CLI 入口：只做参数解析与 IO 呈现
├── src/               # 业务逻辑（按职责拆分，禁止巨型文件 > 300 行）
├── test/              # 测试 + mock
└── README.md          # 项目手册（命令、用法、示例）
```

## 4. 函数与注释

- 每个导出函数写 JSDoc：参数、返回值、副作用；
- 复杂逻辑必须注释「为什么这么做」（决策理由 > 复述代码）；
- 注释语言：中文（面向团队）或中英混合，保持一致性；
- 不写废话注释（`// i++ 自增` 这类禁止）。

## 5. 错误处理

- 用户可修复的错误：给出**可执行的下一步**（如安装命令）；
- 封装层错误：抛出 `MulticaError`，携带 `cmd`、退出码、stderr；
- 进度/日志走 `stderr`，**stdout 只输出最终结果**（保证 `--json` 可解析）；
- 不吞异常；顶层入口统一 `catch` 打印 `✗ 消息` 并 `exit(1)`。

## 6. Git 提交规范

提交信息格式（Conventional Commits）：

```
<type>(<scope>): <subject>

type: feat | fix | docs | refactor | test | chore | style
scope: 模块或命令名（可选）
subject: 中文或英文，动词开头，不超过 50 字
```

示例：

```
feat(dispatch): 支持 --agents-file 从 JSON 加载 Agent 列表
fix(multica): issue children 返回结构兼容按 stage 分组
docs(ForAgentDev): 新增 05-协作规则
```

- [ ] stdout 无多余日志（`--json` 可解析）
